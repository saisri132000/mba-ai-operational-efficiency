The complete project in one minute

We analyze genuine published OECD survey tables to describe AI adoption, perceived productivity and performance, task changes, decision assistance, and implementation barriers in finance and insurance and manufacturing.

What goes in?

Published weighted proportions in an Excel workbook, supported by the original research PDF.

What happens?

Python extracts specific cells, checks their validity, calculates descriptive comparisons, and generates the deliverables.

What is achieved?

A transparent, reproducible secondary analysis with source-traceable tables, charts, and report.
The completed report uses 2022 survey evidence published in 2023. It is not a Chennai survey, a current adoption census, or evidence of causation. The earlier Chennai primary-survey proposal is a separate design.

1. How are we taking the input?

The user supplies an OECD Excel workbook. The script rebuild.py reads it locally using openpyxl. The source PDF explains the original study, methods, questionnaire wording, and interpretation. The numerical calculations read the workbook.

Where did the evidence originate?

The OECD surveyed employers and workers in Austria, Canada, France, Germany, Ireland, the United Kingdom, and the United States. The original study reports 2,053 firms and 5,334 workers overall. This project did not recruit those participants.

Our unit of analysis is a published estimate. The 152 extracted estimates are not 152 respondents. The workbook contains aggregate percentages, not individual questionnaire records.

3. How are we calculating the output?

A. Percentage

Multiply the published proportion by 100.

0.567 × 100 = 56.70%

percentage = proportion * 100

56.70% report positive effects. This is not a measured 56.70% productivity increase.

B. Sector difference

Subtract finance from manufacturing.

62.60 − 56.70 = +5.90 pp

difference = manufacturing - finance

The positive-response share is 5.90 percentage points higher. This is not a significance test.

C. Combine answers

For finance workers, Figure 3_3!B32 and B33 are improved a lot and improved a little.

(0.303 + 0.490) × 100 = 79.30%

79.30% of the relevant AI-using workers report improved own performance.

Validation: what we check and what we cannot claim

The script checks numeric proportions are within 0–1. Complete response distributions must total approximately 100%, with 0.2 percentage points allowed for rounding. Do-not-know responses remain separate. Overlapping task indicators are not incorrectly added into a single distribution.

A genuine source issue: Finance staff-cost motivation in Figure 3_1 sums to 94%, despite its displayed 100% total. We preserve and flag it, and exclude it from comparative conclusions. We do not normalize it or invent the unexplained 6%.

The package records 36 distribution checks: 35 pass and one source item is flagged. Source references remain attached to the extracted estimates.

Correct explanationIncorrect explanation
56.7% of relevant employers reported positive effects.Productivity increased by 56.7%.
A descriptive difference of 5.9 percentage points.A statistically significant causal effect.
Costs are a reported adoption barrier.The project proves actual financial savings.
Secondary analysis of OECD evidence.Primary findings from Chennai respondents.

No new correlations, regression, Cronbach's alpha, p-values, or confidence intervals are calculated from these aggregate tables. Increased task pace may indicate faster execution or work intensification; it is not automatically an efficiency benefit.

Common viva questions

What did you personally do?

Defined the secondary-data scope, extracted and validated selected published estimates, calculated descriptive comparisons, and produced reproducible charts, report, and interpretation. OECD researchers conducted the original surveys.

Why did the original Chennai project change?

Genuine primary responses were unavailable. The completed report transparently adopts a secondary design using the supplied OECD evidence. The source population and measures are explicitly different.

Does AI cause better productivity?

This analysis cannot establish causation. It describes reported perceptions among surveyed users/adopters and descriptive sector differences.

Why use Databricks without machine learning or regression?

The questions are descriptive and the workbook is small. Databricks is the requested notebook execution environment for the same Python pipeline. More software cannot replace missing individual-level evidence or make aggregate perceptions causal.

What are the managerial recommendations?

Start with a bounded operational pilot. Track cycle time, errors, rework, service quality, and cost per transaction. Include training, oversight, integration, and maintenance costs. Keep human review for consequential decisions. These are proposed practices, not outcomes proven by this analysis.

What remains before submission?

Institutional acceptance of the secondary design, plus required identity details, declarations, signatures, and formatting. No approval or signature is fabricated.

Run the actual analysis

Extract the submission ZIP. In its root folder, use Python 3.10 or later and run the documented Windows commands:

python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python rebuild.py

Dependencies: openpyxl reads the workbook, reportlab creates the PDF, and pypdf checks the generated PDF. The script regenerates results, charts, reports, references, and the explanation guide.

The included Databricks_OECD_Analysis.py notebook installs the same requirements and calls the same build. This standalone explainer works offline and embeds the existing calculated results. It does not import new questionnaire responses or run the Python pipeline inside the browser. Its arithmetic calculator is educational.
